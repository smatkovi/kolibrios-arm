# Bringing it up on the N950

Nothing of this has run on the device yet. The steps, in the order that
risks least:

## 1. What the display looks like under Linux

On the N950 under Harmattan or Leste, as root:

```sh
sh tools/n950-dss-dump.sh > dss.txt
```

It only reads registers. `kernel/platform/n950.c` assumes that the boot
loader leaves DISPC's graphics layer on a frame buffer in RAM (DISPC_GFX_BA0,
its size in DISPC_GFX_SIZE, a 16 or 32 bit format) and that the DSI link
to the panel stays up, so that DISPC_CONTROL's GOLCD and LCDENABLE send
one frame (command mode panels work frame by frame). The dump shows
whether that holds, and what NOLO itself sets.

## 2. Start from RAM, without writing the flash

NOLO loads a kernel into RAM and starts it, from the PC over USB:

```sh
0xFFFF -m build/n950/kernel.bin -l -b        # or Nokia's flasher: -k ... -l -b
```

(the N950 switched off, connected while the tool waits). The image is
linked at 0x80008000, where NOLO puts a kernel. It writes nothing to the
flash; switching off brings the phone back to its own system.

What to expect: the KolibriOS desktop on the screen (the panel, the
example window, the clock). A kernel panic shows its message in a red
bar at the top of the screen, since there is no serial port at hand.
Touch and keyboard do not work yet.

## 3. From ubiboot

The image carries a zImage head (magic 0x016f2818 at 0x24), so ubiboot
can start it with kexec like a Linux kernel: a third entry beside MeeGo
and Leste in ubiboot.conf (see smatkovi/n950-maemo-leste). There Linux
(ubiboot's kernel) has set up the display before kexec.
