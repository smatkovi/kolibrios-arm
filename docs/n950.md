# Bringing it up on the N950

Nothing of this has run on the device yet. The steps, in the order that
risks least:

## 1. What the display looks like under Linux

On the N950 under Harmattan or Leste, as root:

```sh
sh tools/n950-dss-dump.sh > dss.txt
```

It only reads registers. `kernel/platform/n950.c` assumes that the boot
loader leaves DISPC's graphics layer on a frame buffer in RAM (DISPC_GFX_BA0,
its size in DISPC_GFX_SIZE, a 16 or 32 bit format) and that the DSI link
to the panel stays up, so that DISPC_CONTROL's GOLCD and LCDENABLE send
one frame (command mode panels work frame by frame). The dump shows
whether that holds, and what NOLO itself sets.

## 2. Start from RAM, without writing the flash

NOLO loads a kernel into RAM and starts it, from the PC over USB:

```sh
0xFFFF -m build/n950/kernel.bin -l -b        # or Nokia's flasher: -k ... -l -b
```

(the N950 switched off, connected while the tool waits). The image is
linked at 0x80008000, where NOLO puts a kernel. It writes nothing to the
flash; switching off brings the phone back to its own system.

What to expect: the KolibriOS desktop on the screen (the panel, the
example window, the clock). A kernel panic shows its message in a red
bar at the top of the screen, since there is no serial port at hand.
Keyboard and touch screen are written but untried: the kernel's
debug board (`board` in the menu) says whether the maXTouch and the
keypad answered, and the touch directions may need turning.

## 3. From ubiboot, next to Leste

The image carries a zImage head (magic 0x016f2818 at 0x24), so ubiboot
starts it like a Linux kernel. smatkovi/n950-maemo-leste's image puts it
on Leste's partition: `KOLIBRI_BIN=build/n950/kernel.bin` for its
`rootfs/build.sh` copies it to p4's `/boot/kolibri.bin` (the release
images from leste-20261029 on have it), and its `install/n950-install.sh`
then makes KolibriOS the second kernel line of ubiboot's "Maemo" entry:

    G_OS5_NUM=2
    G_OS5_AUTOBOOT=0                # ubiboot asks which line; 1 = Leste at once
    G_OS5_2_LABEL="KolibriOS (test)"
    G_OS5_2_FILE="/boot/Maemo/boot/kolibri.bin"

(`/boot/Maemo` is ubiboot's link to the mounted p4.) Choosing it, ubiboot
runs `kexec -l <file> --type=zImage --command-line=...` and `kexec -e`
with its kexec-tools 2.0.3: the image goes to the lowest free RAM plus
0x8000, that is 0x80008000 where it is linked, the ATAGs to 0x80001000
(r2; ignored here, as is the command line from Leste's `/boot/cmdline`),
MMU and caches off. Before that, ubiboot's own kernel (2.6.32, omapfb) has
the panel on and DISPC's graphics layer on its frame buffer near the top
of the 1 GiB, outside the 256 MiB this kernel uses; `n9_display_init`
maps that buffer uncached and draws into it.

Order for the first test on the phone:

1. Under Leste (or Harmattan), as root: `sh tools/n950-dss-dump.sh >
   dss.txt` (step 1; Leste's kernel has /dev/mem). It shows the
   display as a Linux left it, which is what this kernel takes over.
   ubiboot's omapfb is another Linux than the one that made the dump, so
   the dump says what to expect rather than what ubiboot leaves.
2. Reboot into ubiboot, choose "Maemo", then "KolibriOS (test)".

What it should show: KolibriOS's Hildon-style desktop in landscape (the
status bar with the application button at the top left and the clock,
the clock widget, the hint "The applications: the button at the top
left"), as `make run` shows it in QEMU. Panics show their text in a red
bar at the top. The turn of the picture (`n9_display_flush`) and the
touch directions are guesses until seen; the keyboard and the touch
screen are polled and untried; the debug board (`board`, from the
application menu) says whether the maXTouch and the keypad answered.
There is no RTC driver yet: the clock starts at 00:00 on 1 January 1970.

Back: hold the power key until the phone switches off, then start it
again; nothing of this writes the flash or the eMMC, Leste and Harmattan
stay as they were.

From a running Leste instead (no ubiboot menu, the display as Leste's
omapdrm left it): `apt install kexec-tools`, then `kexec -l --type=zImage
/boot/kolibri.bin && sync && kexec -e`. Untried as well.
